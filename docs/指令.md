## 2. 提出原始需求，与 ChatGPT 讨论

我现在有这样一个需求：

希望开发一个可以独立复用的 Android NFC Reader Module，未来其他 Android 项目可以直接接入使用。

本期需求比较简单，主要支持标准 NFC NDEF 标签中的两种常见内容：

1. Text；
2. URL / URI。

工程希望分成两个 Module：

* `nfc-reader`：独立 NFC 能力模块；
* `app`：用于展示和验证 NFC Module 的 Demo。

Demo 希望只做一个页面。

页面顶部有标题和“演示模式”开关。

演示模式开启时：

* 展示模拟 Text 标签按钮；
* 展示模拟 URL 标签按钮；
* 可以模拟 NFC 标签触碰；
* 模拟数据也应该尽量经过 NFC Module 的真实解析链路，而不是 UI 直接伪造结果。

演示模式关闭时：

* 隐藏模拟按钮；
* 使用真正的 Android NFC 能力读取标签；
* 页面展示实际读取结果。

读取结果需要清楚展示 Text、URL、读取状态等内容。

界面简单、清新即可，不希望为了 Demo 做复杂架构。

Module 最终希望做到别人能够拿去接入，因此 API 要简单，并且最后需要提供一份对外接入文档。

现在先不要写代码。

请站在 Android Module 可复用和实际交付的角度，和我一起分析这个需求：

* 需求是否完整；
* Module 和 App 应该怎样划分职责；
* API 应该怎样设计；
* NFC Text / URL 有哪些必要边界；
* 生命周期和异常需要注意什么；
* 哪些能力本期不应该做，避免过度设计；
* 最终怎样判断这个需求已经达到可交付状态。

我们先把需求讨论清楚，再进入开发。
